# Issue

**Title:** Fix off-by-one in MSD time intervals

## Description

The ASE, MDAnalysis and pymatgen parsers insert a copy of the first frame, which gives a zero row in `displacements`. `calculate_msd`/`calculate_mstd` also use `displacements['obs', di - 1]` as the time-origin sample. With the zero row present, that sample covers `di - 1` steps rather than `di`, and `dt` runs one interval past the end of the trajectory.

Example: a particle moving 0.1 Å per frame over 6 frames gave MSD `[0.0042, 0.017, …, 0.1025, 0.125]` at dt = 1…6. The correct values are `[0.005, 0.02, …, 0.125]` at dt = 1…5.

**Change:** remove the duplicated first frame from the three parsers.

**Impact:** reported MSD, D, D_J and σ values change, most at long time intervals. `displacements` now has `n_frames - 1` observations, and the shape assertions in `test_analyzer.py` are updated to match. The padding produced a zero row for the old `disp[i:] - disp[:-i]` scheme; the `di - 1` origin term added in 2024 double-counts with it. Please confirm this is the intended convention.

**Tests:** `test_ase.py::test_msd_matches_brute_force` checks the MSD against brute-force pairwise displacements.
