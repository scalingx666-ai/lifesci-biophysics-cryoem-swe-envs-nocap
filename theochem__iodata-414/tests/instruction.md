# Issue

**Title:** Keep lines starting with # as data inside WFX sections

## Description

A WFX file written by IOData cannot be loaded again when the title starts with `#`. The MWFN files written by Multiwfn have the title `# Generated by Multiwfn`, so converting one of those to WFX gives a file that fails with `Expecting one value, got 0`.

The cause is that `parse_wfx` skips every line starting with `#` as a comment, also inside a section, so the `<Title>` section ends up empty.

This skips such lines only outside sections, and keeps them as data inside a section. Comments at the top of the file, as in `h2_ub3lyp_ccpvtz_with_comments.wfx`, work as before. The only behavior change is for a `#` line inside a section, which was ignored before and is now treated as content. Let me know if you would rather keep ignoring those and handle only the title, I can change it.

The new test dumps a water WFX file with the title `# Generated by Multiwfn` and loads it again. It fails on the current code and passes with this change. The full test suite passes (`pytest iodata`), and `ruff check` and `ruff format` are clean.

I found it by loading the sample files and dumping them to the other formats. I used an LLM assistant (Claude Code) for that and for the change, and I checked the results.
