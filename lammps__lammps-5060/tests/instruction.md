# Issue

**Title:** Add triclinic-box support to pppm/disp (and its omp/tip4p variants)

## Description

## Summary

This pull request adds triclinic (non-orthogonal) simulation box support to the
dispersion PPPM solver `pppm/disp` and its accelerated/TIP4P variants
(`pppm/disp/omp`, `pppm/disp/tip4p`, `pppm/disp/tip4p/omp`), bringing them in
line with the triclinic capability the regular `pppm` style already has. The
particle-side machinery (lamda-coordinate particle mapping) was already
triclinic-aware; this PR adds the missing reciprocal-space half.

Support is limited to **ik differentiation** (as in the base `pppm` style;
`kspace_modify diff ad` is rejected for a triclinic box) and, for the slab
correction, to the **EW3DC volume-factor variant with an xy tilt only**
(xz = yz = 0, so the slab normal stays the z axis). For the TIP4P variants the
slab correction is not (yet) combined with a triclinic box.

The work is organized into reviewable commits:

1. **KSPACE core** – `setup_triclinic()`, the coulomb and dispersion triclinic
   Green's functions, and triclinic gradient branches in `poisson_ik`,
   `poisson_2s_ik`, and `poisson_none_ik` (with per-atom energy and virial).
   Covers all dispersion mixing modes (geometric / arithmetic / per-type) and
   combined coulomb+dispersion.
2. **OPENMP** – enables triclinic for `pppm/disp/omp` (the threaded
   make_rho/fieldforce already operate in lamda coordinates, so the
   reciprocal-space setup/solve are inherited unchanged).
3. **Slab** – the EW3DC slab correction for a triclinic box.
4. **TIP4P** – the M-site reconstruction (`find_M`/`find_M_thr`) for triclinic
   boxes, mirroring the already-triclinic `pppm/tip4p` variants.
5. **Tests** – force-style regression tests for the new cases.

## Backward Compatibility

Fully backward compatible. The orthogonal code paths are unchanged (the only
edit visible to an orthogonal run is rewriting `if (triclinic == 0) prd =
domain->prd; else prd = domain->prd_lamda;` to `prd = domain->prd;` in four
grid-sizing helpers, which is identical for `triclinic == 0`). Previously a
triclinic box with `pppm/disp` produced a hard error; it now runs.

## Implementation Notes

- The reciprocal-space wave vectors are no longer separable for a triclinic
  box, so `fkx/fky/fkz` (and the order-6 analogs) are built per FFT grid point
  via `x2lamdaT`, and the xy-gradient packing used in the orthogonal Poisson
  solvers is replaced by separate per-direction (and, for the paired/per-type
  solvers, per-density) gradient FFTs.
- Two issues surfaced and were fixed along the way: the dispersion grid sizer
  used the lamda (unit-cube) box for a triclinic box and produced a degenerate
  2x2x2 grid (fixed to use the real box, matching `set_grid_global`); and the
  `slabcorr()` call in `compute()` was moved ahead of the lamda->box coordinate
  conversion, since the slab dipole correction needs Cartesian z-coordinates.
- The `/omp` and `/tip4p/omp` variants required only enabling the
  `triclinic_support` flag (plus the TIP4P M-site `find_M_thr` branch); they
  inherit the rest from the base classes.

## Validation

For every newly enabled case the triclinic result was checked to reproduce the
orthogonal code path to round-off at zero tilt, to match the `ewald/disp`
reference (which supports triclinic) to grid accuracy at finite tilt with no
tilt-specific error, to give correct per-atom energy and stress, and to be
deterministic across MPI ranks and OpenMP threads. The new force-style tests
also exercise the `/omp` variants automatically; all 56 `KSpaceStyle` unit
tests pass.
