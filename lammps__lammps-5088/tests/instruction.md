# Issue

**Title:** Allow setting fix wall/gran wall positions via equal-style variables

## Description

**Summary**

This pull request adds support for setting the *lo* and *hi* wall positions of the *xplane*, *yplane*, and *zplane* wall styles of fix wall/gran through equal-style variables, so the walls can move during a run, for example to model a piston compressing a bed of granular particles.  Since the damping and friction terms of granular contact models depend on the relative velocity between particle and wall, the wall velocity is inferred from the change of the wall position between consecutive timesteps -- the same approach used for moving regions by `Region::set_velocity()`, and thus consistent with what fix wall/gran/region users already get.  Each particle uses the velocity of its nearer wall, so the *lo* and *hi* walls can move independently.

**Backward Compatibility**

No changes for existing inputs: constant wall positions take exactly the same code path as before.  One new runtime check stops with an error when the *lo* wall position does not remain below the *hi* wall position; this can only trigger for geometries that were already unphysical and previously processed silently.

**Implementation Notes**

- The wall velocity is computed as (current - previous position) / dt, mirroring `Region::set_velocity()`: it is zero at the very first evaluation, and re-evaluations on the same timestep (setup of a continued run) keep the previous velocity, like the `vel_timestep` guard used for regions.
- The triplicated *xplane*/*yplane*/*zplane* parsing in the constructor was collapsed into one block, so the variable handling exists only once.
- All variable evaluations in the fix (including the pre-existing wall *temperature* variable, also in fix wall/gran/region) are now bracketed with `clearstep_compute()`/`addstep_compute()`, so position and temperature variables may reference computes.
- fix wall/gran/region needs no changes (regions provide their own motion, with the velocity inferred the same way).
- The KOKKOS version derives from the frozen pre-GranularModel implementation in `fix_wall_gran_old.cpp` and does not support this feature; it now stops with a specific error message when a wall position variable is used (verified with a KOKKOS serial build).

Verification performed:

- Galilean invariance: a particle bouncing on a wall moving at constant velocity (ramp variable) reproduces the trajectory of a boosted twin simulation (static wall, particle velocities shifted) to machine precision (max position deviation 7e-15 over 5000 steps), separately for the *lo* wall and the *hi* wall, which also covers both branches of the per-particle nearer-wall velocity selection and proves the inferred velocity enters the contact model exactly like a prescribed one.
- Run continuity: splitting a run into `run 2000` + `run 3000` reproduces the single `run 5000` trajectory to within one ulp for the variable-driven wall (the same experiment with the *wiggle* keyword shows a pre-existing artifact of order 1e-8), confirming the wall velocity is carried across run boundaries.
- A particle riding a slowly oscillating overdamped wall tracks the *wiggle* reference to within 3e-5 in position over 6000 steps, confirming the finite-difference velocity approximates the analytic one for smooth motion.  (Trajectories of particles *bouncing* on an oscillating wall diverge visibly from the *wiggle* reference after a few thousand steps: the O(dt) difference between the finite-difference and the analytic wall velocity is exponentially amplified by the chaotic bouncing dynamics.  This is inherent to the velocity inference and equally applies to moving regions.)
- A squeeze test (variable-driven floor rising against a constant ceiling) with the position variable referencing a compute runs correctly, confirming the clearstep/addstep bracketing; a 4-rank MPI run reproduces the serial thermo output.
- All error paths were tested and produce the intended messages (*wiggle*/*shear* conflict, undefined variable, non-equal-style variable, crossing walls at runtime, position variable with the KOKKOS variant).
- All 44 granular DEM unit tests pass; `make check` style checks pass; the documentation builds without new warnings or spelling issues.
