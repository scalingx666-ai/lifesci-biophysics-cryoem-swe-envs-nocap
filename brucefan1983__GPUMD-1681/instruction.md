# Issue

**Title:** perf(dp): run compact canonical graphs on device

## Description

**Summary**

Follow up on #1679 by running compact canonical DeepMD artifacts, including compressed DPA4C, through their native device ABI instead of the standalone `DeepPot::compute` path. The change is confined to `src/force/dp.cu`; `neighbor.cu` and the class layout are unchanged.

**Implementation**

GPUMD's filtered neighbor list is already destination-major. The new branch builds the remaining compact canonical ABI arrays on the GPU: int64 model types, uint32 source indices, float32 edge vectors, destination CSR, source CSR, and the source-edge permutation. It then calls `DeepPot::compute_canonical_graph_gpu`. Existing edge/vector and ordinary graph artifacts continue to call `compute_edges_gpu`, while small cells that require explicit periodic images keep the existing standalone route. Existing DP scratch buffers are reused so this remains a one-file change.

**Why this is a GPUMD fix**

The same compressed artifact succeeds through the DeepMD Python API and LAMMPS Kokkos. GPUMD 5.7 originally sent it to `compute_edges_gpu`, which DeepMD correctly rejected with `compute_edges_gpu cannot serve a compact canonical artifact; use compute_canonical_graph_gpu.` PR #1679 fixed that crash by routing the artifact through standalone compute. This follow-up connects the intended canonical GPU entry point and removes the large performance penalty of that correctness fallback.
